# Getting help

Start with [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md).
For a first run, follow the [tutorial](docs/guides/tutorials/first-check.md); for
errors and exit codes, see [troubleshooting](docs/guides/how-to/troubleshooting.md).
For specific contracts, read [source binding](docs/SOURCE-BINDING.md),
[the evidence mapper](docs/EVIDENCE-PAPER.md),
[scalar control](docs/SCALAR-CONTROL.md), and
[verification scope](docs/VERIFICATION.md).

Use [Issues](https://github.com/Akilleez-QA/foundation-math/issues/new/choose) for reproducible
bugs (the **Bug report** form is the problem report) and feature proposals (the
**Feature request** form is the change request). Both forms ask for a severity. Include the commit, Python version, operating system,
exact command, expected behavior, and a small synthetic input. For a proposal,
explain the use case, scope, alternatives, and a bounded validation approach.
Search existing issues first and remove private data from all attachments.

For usage questions, open an issue describing your goal, what you tried, and where
you got stuck. Support is best effort with no guaranteed response time. A support
answer does not establish mathematical acceptance or validate a physical model.
Follow [SECURITY.md](SECURITY.md) for sensitive reports and
[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) in project spaces.
